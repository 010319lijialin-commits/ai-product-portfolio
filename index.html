03 / KEY PRODUCT DECISIONS

三个关键设计判断。

为什么先挂载旧知识，而不是创建新笔记？

如果每条输入都新建节点，碎片仍然是碎片。系统优先匹配已有知识位置，将新的观点、案例和反例挂到相应主题下；确有必要时才新建节点。

为什么由 AI 推荐，而不是自动决定？

个人知识体系具有主观性。AI 负责理解输入并推荐位置，用户可以接受、换位置或自建节点。当前代码已有推荐结果校验与挂载记录；挂载采纳率可作为后续评估指标，而不是已经验证的成绩。

为什么把表达练习接到知识地图？

存储不等于掌握。已有功能可以从知识节点生成表达材料，进入录音转写和结构化复盘，再把新观点沉淀回树中，形成输入、输出和反馈的循环。

02 / BUSINESS SYSTEM

进销账.

把进销存、收付款和账务核销组织成清晰、一致的业务流程。

线上体验地址待核实
01 / CORE PROBLEM

业务单据变动，账务关系必须保持一致。

交易、收付款、费用等业务事实相互影响。尤其当历史单据被修改时，需要避免余额和核销关系出现不一致。

02 / CORE FUNCTIONS

从单据出发，重建业务账本。

业务记录

进销存、收付款及相关单据。

规则计算

以原始单据为依据，重算衍生结果。

数据管理

本地保存与导入导出，支持个人使用。

03 / KEY DECISION

先保证账的可信度。

为什么让原始单据成为事实源？

余额和汇总结果应由单据计算，而非手工维护多个可能冲突的状态。结合整数分金额计算，降低计算误差和不一致风险。
